# 「今晚早点」产品概念文档 v5

> v1 = AI 对话助眠搭子（已否定）
> v2 = 早餐双关 + 24h 闭环（过渡）
> v3 = 早点铺经营隐喻（确立世界观，角色/AI/检测均未自洽）
> v4 = 角色与机制全面自洽（用户当店长、面点精灵、目标边界、检测机制）
> v5 = 经营逻辑落地、收集体系理清、与竞品区分明确（当前版本）

> **v5 相对 v4 的核心修正**
> 1. **修掉"打烊"撞车**——"早点卖完"和"店长关灯睡觉"是一天里两件不同的事，不再都叫"打烊"。"打烊"从此只指**夜里关灯歇业**这一次。
> 2. **铺子时间跟现实同步、全天开着、白天有活计**——清晨营业卖早点，白天店长和精灵一起备菜打理，傍晚准备明天，夜里打烊。解决了"白天店该干嘛"的空白。
> 3. **菜品解锁机制定了**——里程碑（熄屏早睡的早晨累积）+ 客人混熟后带菜（关系递进），不靠货币、不靠现实早餐。
> 4. **不引入货币经济（立为设计原则）**——不要"赚钱→升级"循环，铺子的好用情感化方式衡量。"少操作"是特性不是缺陷。
> 5. **拍真实早餐剥离出主产品**——移入"产品家族/未来扩展"，作为姊妹产品。主产品不再有拍照记录早餐。
> 6. **收集体系理清**——两本图鉴（客人=电话本，菜品=菜单）+ 精灵皮肤（在小屋）+ 营业日志（账本，非图鉴）。
> 7. **技术路线明确**——走 Finch 式诚信输入 + `visibilitychange`，而非 Pokémon Sleep 式传感器监测。
> 8. **称呼统一为"店长"**（去掉"老板娘"）。

## 一、一句话定位

你是一家叫「今晚早点」的早点铺的店长。铺子跟着现实时间一起活：清晨开门卖早点、白天和你的伙伴一起备菜打理、夜里你关灯歇业。早睡早起，铺子就热闹、客人就来；晚睡晚起，铺子就安静——但永远不关张，明天还在。不惩罚，不说教，是你生活的一面温柔的慢镜子。

## 二、地基洞察（从未改变）

### v1 的致命矛盾

v1 假设用户凌晨 1 点刷手机时会主动打开 App、跟 AI 对话 10–15 分钟完成诊断→干预→呼吸。矛盾在于：**产品的前提是"用户此刻没有自控力"，但产品的启动恰恰需要自控力。** 而且真正的对手不是 Calm，是抖音小红书。

### 核心洞察：问题不是"怎么入睡"，是"怎么放下手机"

用户原话："身体早就困了只是精神还不困，如果不看手机可能很快就能睡着了，关键就是放不下手机。" **大部分熬夜用户只需要一个理由放下手机，放下之后自己就睡着了。** 这是产品的轴心。

### 三步策略

1. 不在凌晨改变行为（做不到），而在傍晚用户还理智时给一个早点放下手机的理由（预承诺）。
2. 做好记录与正反馈，让用户长期看见自己的作息——且记录是玩世界的副产品，不是额外负担。
3. 用一个想每天打开看看的小世界提供打开动机，把"该歇业了"焊进世界观。

## 三、产品名称双关

- 今晚**早点**（早一些）睡 → 夜里打烊
- 明早**早点**（早餐）吃 → 清晨开门营业

世界观完全建立在这个双关上：你经营一家早点铺，早睡才能早起开门。

## 四、世界观与角色

### 你 = 店长

铺子归你。只有"用户当店长"才能让机制成立："我没睡好 → 铺子明早开不了门 → 我的常客吃不上早餐。" 它带来"养我自己的小世界"的驱动力，避开了 v1"深夜亮灯等你"的坑，并把动机方向从"被提醒该睡了"翻成"我想明早开门，因为阿橘说好要来吃油条"。

> 情感方向：不是"AI 在深夜安慰你"，而是"你照顾你的铺子和客人，它们也在照顾你"——双向关系。为"自己负责的东西"歇着，比为"自己的健康"歇着更推得动一个熬夜的人。

### 面点精灵 = 你的常驻伙伴

详见第六节。一句话：开局即得、人人都有、灵魂由测评定型（六型）、外表是可变的点心形态、一双豆豆眼贯穿始终。它是 AI 在世界里的化身，住在铺子里的一间小屋。

### 小动物 = 轮流来的客人（独立于精灵）

六型小动物是**客人**——来吃早餐、可被收集、轮流出现，且与你的关系会随来访次数递进（见第七节）。它们不进"伙伴"身份，以免与精灵撞车。

### 店规：只做早点、不做宵夜、铺子跟你一起睡

把"该歇了、别熬夜"焊进世界观，不靠 App 跳出来说教。你不是被劝睡的，你是个该按点歇业、好早起开张的店长。

## 五、产品的真实目标边界

**产品管的是"帮用户放下手机"，不是"让用户睡觉"。**

- App 管不到"手机里"（拼不过抖音），但管得到"手机这台设备"（促成放下/熄屏）。
- "放下手机后几分钟睡着"是身体的事，App 不假装能控制。
- 因此**打烊判定 = 放下手机（熄屏 / 不切去刷别的），不是"入睡"。**

> 必须接受的现实：大概率拦不住某一晚熬夜。但"店长 + 断签不清零 + 铺子明天还在"的价值不在赢下今晚，而在**不输掉这个用户**——靠几十个不指责的早晨累积出改变。

## 六、面点精灵（伙伴系统）

### 六条设定

1. **开局即得，人人同款**。无抽卡、不会错过——与"永远站在用户这边"一致。
2. **灵魂由测评定型**。结果对应六型之一（即六套人格 system prompt 的内核）。这让**测评从"贴标签诊断"翻译成"送你一个懂你的伙伴"**。
3. **外表是可变的点心形态**（非换色换装）。本体是一小团白面，随"好好生活"逐步解锁成越来越丰盈的点心形态（小笼包、可颂、甜甜圈……）。这条成长线在讲"你和它一起把日子过得越来越像样了"。
4. **一双豆豆眼贯穿始终**。纯粹因为可爱、是它的标志性表情；连续感靠"它每天都在"维系，不靠长相一致——精灵不被外表拘束。
5. **测评推荐 + 用户确认或换**，外表由用户挑。
6. **角色固定、话题自适应**。它这个"人"不变，对话内核起点是测评结果，但随营业日志的作息变化挪动关心重点（"工作型"的它发现你近期躺下睡不着，会往焦虑那边关心你）。

### 它的小屋（皮肤入口 + 夜间归处）

精灵住在铺子里的一间小屋 / 小衣柜，这一处同时是三件事的家：
- **换装入口**：点进去给它换/看点心形态。
- **皮肤陈列**：解锁过的形态像摆件一样陈列，未解锁是空位/剪影。
- **夜间归处**：你夜里关灯打烊，精灵回小屋睡——把"铺子跟你一起歇着"这条店规落成一个看得见的小动作。

## 七、核心循环：铺子的一天（铺子时间跟现实同步）

铺子全天开着、活着，一天里有不同的活计。**唯一的"打烊"在夜里。**

### 清晨：开门营业（唯一真正"卖早点"的高光时段）

用户早上打开 App = 铺子开门。这一格有**双重任务**，编排节奏是"先迎接、再结算昨天、再开启今天"，绝不一股脑砸信息：
- **先迎接**：精灵用一句带着昨晚记忆的话把人接住，不让他一睁眼就"干活"。开门时刻 = 天然的"我醒了"信号（见第十节）。
- **结算昨天（轻）**：精灵记得你昨晚打烊/熄屏没，铺子状态体现昨晚好坏，皮肤进度在此推进。
- **开启今天**：出餐给来吃早点的客人、看今天来了谁、感受铺子的样子。没有自动数据时，黑板温柔补问"昨晚大概几点放下手机的呀？"

### 上午晚些：早点快卖完

客人渐少，"今天的早点快卖完啦"。强化"早点=只在早晨"的稀缺感（呼应"睡过头就吃不上早点"）。

### 白天 / 下午：备菜与打理（不是打烊，铺子开着）

没有早高峰了，但铺子开着，你和精灵在**备菜、收拾、打理**：择菜、揉面、试新配方、擦柜台、列明天的采购。这一段松弛、无 KPI、纯过日子，并且**给"菜品解锁"找到了世界观里的家**——新菜谱是你和精灵白天一点点研究/备出来的，不是凭空冒出来。备菜也给了精灵全天候陪你的自然理由（一起做事的陪伴，比杵着等你聊天自然）。

> **可爱点缀：午睡。** 下午铺子没生意时，可点一下让你和精灵一起趴柜台打个盹（醒来精灵伸懒腰）。**纯氛围，零机制**——不给奖励、不影响铺子状态、不算任何进度。它只为白天增加烟火气，绝不能成为"白天补觉绕过晚上早睡"的捷径，以免稀释核心信号。

### 傍晚：准备明天 + 预承诺（AI 核心窗口之一）

此刻用户还理智，AI 接得住，是傍晚最有价值的一下：
1. **预承诺 + 卸心事**：精灵问"明天阿橘要来，今晚打算几点关灯歇着呀？"，可展开成"今晚有什么放不下的事吗？"——若用户说"还有个 PPT 没弄完"，趁清醒帮拆："非今晚不可吗，还是明早头脑清楚了半小时能搞定？" 这是 CBT-I"睡前清空大脑待办"的标准做法，用搭档聊天的方式做，不像填表。
2. **明天预告**：把"早睡"翻译成"我答应了客人"，复习"我是店长、客人依赖我"的因果链。

### 夜晚：打烊（你关灯歇业，全天唯一一次，不可改）

到了你设的关灯时间：
1. 精灵先给**通知**：要打烊了。
2. App 出现**打烊界面**——主语是"**铺子要打烊了**/你这个店长该关灯歇着了"，不是"你该睡了"。因为你是店长、因为有"只做早点不做宵夜"的店规，同样的动作就从"被管"变成了"我该收摊歇业了"。这正是"用户当店长"在此解开 v1 的死结。
3. **打烊仪式**：关灯 / 拉卷帘 + 几次呼吸（原"呼吸引导"在此归位），精灵回小屋睡。
4. 仪式最后一屏**不是"晚安"，是"铺子睡了，把手机也放下吧，扣过来放远一点"**——增加"再次拿起的成本"，比话术管用。
5. 完成 = 记录"今晚关灯时间"（即睡眠开始时间，见第十节）。
6. 进入**熄灯陪伴状态**：铺子安静、精灵打哈欠、轻微环境光。可引导"你也可以把屏幕关掉，铺子会自己守夜，明早见"——熄屏是最好的结局。

> 没在设定时间打烊也不催、不提醒、不惩罚——第二天铺子安静一些而已。

## 八、检测机制：从"监控"到"在场证明"

### 能力边界

不窥探用户切到了哪个 App（隐私雷区，也拿不到），只用系统白送的"我的 App 在不在前台"信号：
- **网页 / 原型**：`visibilitychange`——用户切走或熄屏立刻收到通知，切回也立刻知道。hackathon 用它即可。
- **iOS**：进入后台 / 回到前台回调，只知道"我不在前台了"。
- **安卓**：`UsageStatsManager` 太重、要吓人的权限，hackathon 不碰。

### 怎么用：奖励在场，不抓逃跑

**绝不**做成"你敢切走我就记你一笔"的监工（会被卸载、防不住、还制造愧疚，违背灵魂）。反过来用：
- App 在前台亮着 = 没去刷别的 = 这段"留在铺子里"是今晚的成果（只做二元小成就，不刷时长）。
- 中途切走 = 铺子不指责、安静地暗下去；切回来精灵还在，"哎你回来啦"。
- 熄屏 = 最好的结局，铺子自己守夜，重奖留给它。

**测同一件事，一个让人想卸载（监控），一个让人想留下（陪伴）。**

## 九、激励系统

### 总原则：奖励厚度严格对齐"离放下手机睡觉有多近"

| 行为 | 离目标 | 奖励 |
|------|--------|------|
| 熄屏睡觉 | 最近（真正想要的） | 最厚（含稀有皮肤进度） |
| 亮屏安静陪伴 | 次好 | 小肯定，达成即可，**不鼓励刷时长** |
| 切走刷别的 | 远 | 不奖励，**也不惩罚**（铺子安静，明天见） |

### 不引入货币经济（设计原则）

不做"赚钱→升级→赚更多"的循环——那是放置游戏用来制造"再玩一会儿"的钩子，方向是"让你多停留"，与"让你放下手机睡"相反。铺子的"好"不用钱/数值衡量，用**非数值、情感化**的方式：今天来了哪些客人、热不热闹、精灵什么状态。**"少操作"是特性，不是缺陷。**（这不影响商业模式——限定/联名早餐、装饰皮肤内购是真实世界的钱，不是游戏内经济。）

### 当晚反馈：克制到几乎没有

熄灯陪伴状态最多给极轻的环境反馈，且**必须越来越安静**（光渐柔、精灵渐睡、音渐弱），目标是**让屏幕变无聊**到他自然想熄屏。任何"叮！陪伴 5 分钟 +3 分"都是灾难。

### 三种奖励载体（大头在第二天早上兑现）

1. **精灵的话（每天都给，最便宜，情感分量最重）**——开门第一句带着昨晚记忆。熄屏早睡："昨晚你早早熄了灯，今天气色真好"；陪到打烊："谢谢你陪我待到铺子睡着"；熬夜了也不指责："今天铺子有点困，咱们慢慢来"。
2. **铺子今天的状态（中频，走世界观逻辑）**——因果要顺："你昨晚好好打烊了 → 铺子休息好了 → 今天状态好 → 客人愿意上门"，而非赤裸数值。详见第十一节。
3. **精灵新皮肤（低频，长期里程碑，最珍贵）**——三条铁律：① 只靠累计、不靠连续（断了不清零）；② 只有熄屏的夜晚才计入进度；③ 解锁条件要长，才稀有。

### 反向铁律：不惩罚

激励表里"惩罚"那一栏**永远是空的**。熬夜的唯一后果是"铺子今天安静些、客人少些、精灵打哈欠"——**自然结果，不是惩罚**。用户永远不该因打开 App 而愧疚。

## 十、睡眠数据采集（核心循环的副产品）

### 核心转变

不做独立的睡眠检测功能。**核心循环的动作本身就把数据测了：**
- **睡眠开始时间** = 打烊 / 熄屏时刻（用户主动报告"我要放下手机了"，比偷偷监测更好——主动、有仪式感、无隐私窥探）。
- **醒来时间** = 早上开门、打开 App 的时刻。
- **打烊 + 开门首尾夹出一段睡眠窗口**——为世界观本来就要做的两个动作顺带产出了数据。

### 三层归位

| 来源 | 角色 |
|------|------|
| 打烊 + 开门（核心循环白送） | **主力数据源**，取代原本要单独做的 Tappigraphy |
| 用户自报 | **兜底**，仅用于没好好打烊 / 切走熬夜的夜晚补问（黑板） |
| HealthKit / 手环 | **精度增强**，给有设备用户校准，锦上添花 |

### 不防作弊哲学（保留）

不验证、不质疑。铺子从不惩罚晚睡，用户没有作弊动机；骗一个不评判你的 App 没好处——你骗的是自己的账本。

## 十一、铺子状态的"度"

### 原则：跟"近期趋势"挂钩，不跟"昨晚单点"挂钩

只看昨晚 → 一晚好坏让铺子天翻地覆，用户被单次绑架。看近期整体 → **偶尔熬一次几乎不影响铺子**，这是"不惩罚、断签不清零"在视觉上的体现。

### 三档 + 底部保护

- **热闹**：近期作息整体不错。铺子明亮、客人多、有概率出稀有客人。
- **平常**：默认态，绝大多数时候看到的样子，基准线。
- **安静**：近期普遍熬得晚。铺子光柔、客人少、精灵打哈欠。

两条关键的度：
1. **最差也就"安静"，永远不会"关张/凄凉"**。安静 ≠ 荒废。连熬一周，铺子也只是暖光里静悄悄、门照常开、精灵照常在。这道底部保护线是"铺子明天还在"的视觉承诺，绝不能击穿。
2. **向上慢、向下更慢**。变好要几天好趋势累积（让"热闹"值得追求）；变差更迟钝（偶尔一两晚几乎不下掉）。这个不对称是故意的——**让好行为被看见，让偶尔的失手被原谅。**

稀有客人作为"热闹"之上的随机惊喜（可变奖励），不是每次热闹都触发。

> 一句话：铺子状态是你近期作息的一面**慢镜子**——好起来要努力几天，坏下去要连续辜负很久，且永远不会真的冷场。

## 十二、收集与功能体系（剥离早餐拍照后理清）

剥离掉"拍真实早餐"后，主产品里**收集性的东西**就两本图鉴，加上精灵皮肤和营业日志（后两者不是图鉴）。**入口沿用界面设计文档里已定的铺子物件，不另造。**

| 东西 | 是什么 | 入口（铺子里的物件） |
|------|--------|---------------------|
| **客人图鉴** | "我认识了铺子里多少位客人" | **电话本 / 联络簿**（柜台上一本翻旧的小册子） |
| **菜单（菜品）** | "我这铺子的手艺攒到什么程度" | **菜单板**（墙上的木质菜单牌） |
| **精灵皮肤** | "我和我的伙伴走了多远"（非图鉴） | **精灵的小屋**（见第六节） |
| **营业日志** | "我自己最近过得怎么样"（非图鉴，数据回看） | **账本**（柜台上一本厚账本） |
| 留言板 | 客人留下的便签、铺子的碎语（装饰收集，非数据） | **黑板 / 留言板** |
| 白噪音 | 雨声/风声等助眠音频（优先级低，demo 可省） | **收音机** |

### 客人图鉴（电话本）

每位来过的客人一页档案：长相、名字、性格签名、最爱的早餐、来店次数、第一次来的日期，**以及（v5 新增）你俩的熟络程度**。未解锁是模糊剪影。

### 菜单（菜品）

你这铺子会做哪些早点的总览。每道菜一格：插画、名字、哪些客人爱点、怎么解锁来的。未做过的是剪影。
> **删除**：老界面文档里"早餐墙翻牌（正面真实早餐照、背面数字早点）"的交互——随拍照剥离一并去掉（见第十六节）。

### 营业日志（账本）

形态是柜台上一本手写账本（不是科技感仪表盘）。内容两层：
- **每天一行的流水**：几点开门（=几点醒）、几点关灯（=几点睡/放下手机）、夜里安静陪到打烊还是中途出门、来了几位客人。
- **翻回去看的趋势**：攒一两周后看出近期节奏（普遍几点关灯、最早/最晚是哪天、连着早睡了几个早晨）。**这一层是产品真正的"健康产出"**——不是数字仪表盘，是"翻着自己的账本看见自己最近过得怎么样"。精灵在此偶尔插一句温柔的店长解读（"这周你周三总关灯最晚，是不是周三有什么固定的事？"）。

## 十三、菜品解锁机制

菜品由"睡眠/早起"驱动，在世界内部解锁，**不靠货币、不靠现实早餐**。两条线：
1. **里程碑解锁**：累积"熄屏早睡的早晨"，攒到一定程度，你和精灵在白天备菜时"研究出"一道新菜。
2. **客人混熟后带菜（关系递进）**：客人不会第一次来就掏家乡菜——那像发奖励的机器。**来熟了才教**：生客 → 来几次成常客 → 熟客了，某天才说"我教你做我老家那道吧"。解锁一道菜 = 你和这位客人处出了交情的证明，给客人系统加了一条暗线。

## 十四、与动物餐厅的区分（路演用）

动物餐厅的内核是不停点击招募客人、客人付钱赚货币、用货币解锁升级设施和数百种菜谱、雇员工减少操作——**一个奖励"在 App 里花时间、多操作、多回来收钱"的全天候放置经营游戏。**

我们的根本区别可浓缩成一句对比：

> **动物餐厅：全天候经营，操作越多赚得越多，奖励你停留在 App 里。**
> **今晚早点：只在清晨营业，几乎不用操作，奖励你在现实里早睡早起、然后放下手机。**

具体差异：不要货币经济（情感化衡量铺子的好）；少操作是特性；菜品靠睡眠+客人解锁而非货币；只在清晨真正营业、白天是安静的备菜与陪伴空间；技术走 Finch 路线而非传感器监测。

## 十五、技术架构与可行性

### 为什么不做 Pokémon Sleep 式传感器监测

Pokémon Sleep 要把插着电、开着不熄的手机正面朝下放床垫上，整夜用加速度计 + 麦克风测体动和声音。对我们：
- **网页 demo 做不到**——浏览器拿不到整夜后台的传感器，一熄屏/切走就被挂起。
- **就算做原生也很重**——整夜前台运行、电量、录音权限，不符合"最低技术成本"；**更要命的是方向相反**：它要你把开着的手机留床头，我们要的恰恰是你把手机放下、熄屏、走开。照搬它等于背叛自己的核心。

### 我们走 Finch 路线（诚信输入 + visibilitychange）

Finch 不做传感器睡眠监测，靠"诚信勾选 → 宠物成长"，技术极轻、情感和留存却极强，且气质（无惩罚、不羞辱、问你感觉而非成就）与我们一致。我们的"打烊 + 开门"本质就是 Finch 式诚信输入。

### 技术栈
- 前端：React 网页端原型（hackathon）；正式版可 React Native / Flutter。
- 放下手机判定：`visibilitychange`（前后台 + 熄屏），网页即可跑通，零传感器、零隐私负担、零电量问题。
- 睡眠数据：打烊（关灯）+ 开门（醒来）由核心循环产出；自报兜底；HealthKit / Health Connect 增强。
- AI：Claude API，**六套人格 prompt 保留启用**（决定精灵灵魂内核）；重心在清晨（开门回应、记得昨晚）与傍晚（预承诺、卸心事），外加营业日志的店长解读；凌晨绝不主动出现；话题随作息自适应。
- 存储：本地为主（睡眠记录、客人图鉴、菜单、精灵皮肤进度）；云端可选。

## 十六、产品家族 / 未来扩展

### 「早晨日记」——拍真实早餐（剥离为姊妹产品）

"拍真实早餐"一直接不进主产品世界观，根子是它与主产品**目标不同、行为方向也不同**：主产品核心是"晚上放下手机睡觉"，拍早餐是"白天记录生活"。硬焊在一起既别扭、又把焦点从睡眠带偏。

剥离为一个独立的小产品后两边都解放：主产品专心做早睡早起，世界观干净自洽；早晨日记是一本纯粹的、Finch 式的"早晨相册"——拍下今天的早餐，不评判、不惩罚，空格补不回来，就是"我在好好生活"的证据，不依赖睡眠机制、任何想记录早晨的人都能用。

两者是天然的**产品家族**：共享"今晚早点"的名字与双关、共享面点精灵 IP、共享治愈不评判的灵魂。将来做大，「今晚早点」是作息线、「早晨日记」是生活记录线，精灵在两个产品里是同一只。**但 hackathon 阶段只做主产品，早晨日记仅记一笔在此。**

### 其他未来方向

铺子装修/个性化深度；社交（看朋友的铺子，优先级低）；商业模式落地（限定/联名早餐、装饰皮肤内购，**绝不卖"补回断签"**）。

## 十七、产品灵魂（不变，且 v5 把它落成了机制）

1. **永远站在用户这边，失败时尤其如此。** 铺子安静一天不是惩罚，是"没关系，明天见"。
2. **不替用户做决定。** 几点关灯你说了算。
3. **不评判。** 早餐不分健康不健康，熬夜不分好坏，铺子只记录。
4. **不假装能解决根本问题。** 不承诺让你早睡，承诺的是：无论今晚怎样，明天它都在，而且温柔。
5. **不让用户因打开 App 而愧疚。** 检测用于奖励在场而非抓逃跑；激励表里没有"惩罚"那一栏；不引入"赚钱→停留"的货币钩子。

## 十八、赛道契合与评审对齐（路演用）

**赛道：AI + 健康生活。**
- **健康场景命中**：直接落在"健康习惯养成、身心情绪调节、精细化健康提醒"上。
- **AI 看得见**：用户真的在跟面点精灵对话，由六套人格 prompt 驱动、记得你、每天不同——满足 AI 赛道想要的"亲眼看见在和聪明 AI 互动"。
- **AI 不在凌晨干预**：重心在早晚两个用户接得住的窗口，正面回应"凌晨没有自控力"的洞察。
- **健康产出看得见**：营业日志 + 精灵的店长解读，把作息改善具象化。
- **低技术成本、强落地**：检测靠 `visibilitychange`，数据靠核心循环副产品，符合 Vibe Coding 理念。

**路演叙事**："我们最初做了一个 AI 对话助眠 App。但我们自己问：凌晨 1 点刷手机的人会打开它吗？答案是不会。于是我们重新思考——从'帮你入睡'变成'一家你自己经营、清晨才营业的温柔早点铺'。所有旧功能没被扔掉，而是在新框架里找到了更好的位置。" 这个"做了→质疑→进化"的叙事本身就是最有力的展示。
