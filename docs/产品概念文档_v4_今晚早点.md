# 「今晚早点」产品概念文档 v4

> v1 = AI 对话助眠搭子（已否定）
> v2 = 加入早餐双关 + 24h 闭环（过渡版）
> v3 = 早点铺经营隐喻（确立世界观，但角色定位、AI 位置、检测方案均未自洽）
> v4 = 角色与机制全面自洽（当前版本）

> **v4 相对 v3 的核心修正**：
> 1. 角色定位拍板——**用户是老板，不是顾客；AI 不是"店长"，是铺子里的一只面点精灵伙伴**。（修正了 v3 第一句"你开了一家铺子"与后文"店长 AI"之间的矛盾。）
> 2. AI 定位拍板——不再"待定/可砍"，确立为面点精灵，重心在早晨与傍晚两个用户接得住的窗口。
> 3. 产品目标边界拍板——产品管的是"**帮用户放下手机**"，不是"让用户睡觉"。
> 4. 检测机制拍板——用前后台/熄屏信号判断在场，且**从"监控"翻译为"在场陪伴的证明"**。
> 5. 激励系统、铺子状态的"度"、睡眠数据采集，全部重构为彼此咬合的闭环。

---

## 一、一句话定位

你开了一家叫「今晚早点」的早点铺。你是老板娘，铺子归你。早睡早起，铺子就热闹、客人就来；晚睡晚起，铺子就安静——但永远不关门，明天还在。不惩罚，不说教，就是你生活的一面温柔的慢镜子。

## 二、为什么从 v1 走到 v4

### v1 的致命问题（地基性洞察，从未改变）

v1 假设用户在凌晨 1 点刷手机时会主动打开 App、跟 AI 对话 10–15 分钟完成诊断→干预→呼吸引导。

致命矛盾：**产品的前提是"用户此刻没有自控力"，但产品的启动恰恰需要自控力。** 而且产品真正的竞争对手不是 Sleep Cycle 或 Calm，是抖音和小红书——一个睡眠工具不可能在注意力争夺上赢过几千个工程师优化的信息流。

### 关键洞察：问题不是"怎么入睡"，是"怎么放下手机"

用户原话："身体早就困了只是精神还不困，如果不看手机可能很快就能睡着了。但是关键就是放不下手机。"

大部分熬夜用户不需要 CBT-I 干预、不需要呼吸练习、不需要被诊断成某种人格。**他们只需要一个理由放下手机，放下之后自己就睡着了。** 这条洞察是整个产品的轴心，v4 的所有机制都为它服务。

### v4 确立的三步策略

1. **不在凌晨试图改变行为**（做不到），而在傍晚用户还理智时，给一个"想早点放下手机"的理由（预承诺）。
2. **做好记录和正反馈**，让用户长期看见自己的作息模式——且记录是玩世界的副产品，不是额外负担。
3. **用一个有趣的、想每天打开看看的小世界**，提供持续的打开动机，并把"该歇业了"焊进世界观。

## 三、产品名称双关

「今晚早点」四个字是灵魂：
- 今晚**早点**（早一些）睡 → 晚间打烊
- 明早**早点**（早餐）吃 → 早晨开门 + 早餐记录

世界观完全建立在这个双关上：你经营一家早点铺，早睡才能早起开门卖早点。"早点"既是动机（明早的早餐 = 具象化的"明天的你"），也是奖励（早餐收集）。

---

## 四、世界观与角色（v4 拍板）

### 你（用户）= 店长

铺子归你。这是 v4 最重要的一锤定音，因为只有"用户当老板"才能让所有机制成立：

1. **早睡的因果链只有在这个设定下才通**："我没睡好 → 我的铺子明早开不了门 → 我的常客吃不上早餐。" 如果用户只是顾客，他早睡跟这家店开不开门毫无关系，整个收集系统就悬空了。
2. **它带来"养我自己的小世界"的驱动力**（参考星露谷），这正是"想每天打开看看"的打开动机来源。
3. **它避开了 v1 的坑**。"一家深夜永远亮灯等你的店"听着浪漫，实则邀请你凌晨来坐、把人往熬夜里拉。而"**你**晚上打烊、早上重新开门"，作息节奏握在你自己手里。
4. **动机方向对了**：不是"被提醒该睡了"，是"我想明早开门，因为阿橘说好要来吃油条"——这就是未来自我连续性。

> 情感方向说明：相比 v1"AI 在深夜安慰你"，v4 是"**你在照顾你的铺子和客人，而它们也在照顾你**"——一个双向的关系。很多人不肯为自己歇着，却会为"自己负责的东西"歇着；"为了明早能开门"比"为了你自己的健康"更推得动一个熬夜的人。

### 面点精灵 = 你的常驻伙伴（不是店长，不是客人）

详见第七节。一句话：开局即得、人人都有、灵魂由测试定型、外表是可变的点心形态、一双豆豆眼贯穿始终。它是 AI 在这个世界里的化身。

### 小动物 = 轮流来的客人（独立于精灵）

六型小动物（狐狸、浣熊、兔子、熊、猫头鹰、猫等）是**客人**——来吃早餐、可被收集、轮流出现的一群。**它们不进"伙伴"这个身份**，以免和面点精灵角色撞车。客人是一套更大的卡司，精灵是你专属的、唯一的那一个。

### 店规：只做早点、从不做宵夜、铺子跟你一起睡

这条世界观规矩把"该歇了、别熬夜"直接焊进了设定里，**不需要 App 跳出来说教**。你不是被劝睡的，你是个"到点就该关门歇业、明早好早起开张"的老板。

## 五、产品的真实目标边界（v4 拍板，关键）

**产品管的是"帮用户放下手机"，不是"让用户睡觉"。**

这不是措辞游戏，是目标边界的诚实划定：
- App 管不到"手机里"（拼不过抖音的好玩），但管得到"手机这台设备"（促成放下/熄屏）。
- "他放下手机之后几分钟睡着"是身体的事，App 不假装能控制，也确实控制不了。
- 因此**打烊的判定标准 = 放下手机（熄屏 / 不切去刷别的），而不是"入睡"**。把目标从"让他睡"降到"让他放下手机"，产品立刻变得诚实、而且做得到。

> 必须接受的现实：我们大概率拦不住用户某一晚熬夜。但"用户当老板 + 断签不清零 + 铺子明天还在"这套设定的价值不在赢下今晚，而在**不输掉这个用户**——靠几十个不指责的早晨累积出改变，而不是靠某一晚的拦截。

## 六、面点精灵（伙伴系统，v4 新增详述）

### 它是什么

不是动物（与客人天然区分），是一团会动的小面点精灵——萌、独属于"早点"题材、且能优雅解释"为什么外表可变"。它是 AI 在世界观里的落点。

### 六条拍定的设定

1. **开局即得，人人同款**。没有抽卡、不会错过、谁都不缺一个伙伴——与"永远站在用户这边"一致。
2. **灵魂在测试那刻定型**。测评结果对应六型之一，也就是六套人格 system prompt 各自的内核。这让**测评从"贴标签诊断"翻译成"送你一个懂你的伙伴"**——struggle 被外化成一个懂你的存在，而不是钉在头上的诊断。
3. **外表是可变的点心形态**（不是换色换装）。本体是一小团白面，随"好好生活"逐步解锁成越来越丰盈的点心形态（小笼包、可颂、甜甜圈……）。这条成长线本身在讲"你和它一起，把日子过得越来越像样了"。
4. **一双豆豆眼贯穿始终**。不是为了"证明是同一只"，纯粹因为可爱、是它的标志性表情。
5. **连续感靠"它每天都在"维系，不靠长相一致**。精灵不被外表拘束，每天开门它都在、傍晚它都在，这个"在场"本身就是不变的陪伴。
6. **测试推荐 + 用户确认或换**。"听你刚才说的，这只灵魂大概最懂你——也可以自己挑。" 测评意义保住，老板自主权也保住。

### 外表选择与皮肤解锁

- 开局做完测评后，**外表由用户选**（这是老板的自主权），灵魂已定。
- 后期靠**长期里程碑**解锁更多点心形态——见第七节奖励载体三。
- demo 阶段只做 2–3 款（开局的"一小团面" + 一款已解锁 + 一款锁着的剪影）即可跑通机制；完整品类留作版本规划。

### 话题自适应（角色固定，关心可变）

精灵这个"人"永远不变，对话内核的**起点**是测评结果；但随着营业日志攒起来，它会注意到你作息里的新变化，把关心重点跟着挪（例如一个"工作型"的伙伴，发现你近期总是躺下睡不着，会开始往焦虑那边关心你）。**它一直是同一个它，只是越来越懂你。**

## 七、激励系统（v4 重构）

### 总原则：奖励厚度严格对齐"离放下手机睡觉有多近"

| 行为 | 离目标 | 奖励 |
|------|--------|------|
| 熄屏睡觉 | 最近（这才是真正想要的） | 最厚（含稀有皮肤进度） |
| 亮屏安静陪伴 | 次好 | 小肯定，达成即可，**不鼓励刷时长** |
| 切走刷别的 | 远 | 不奖励，**也不惩罚**（铺子安静，明天见） |

### 当晚反馈：克制到几乎没有

熄灯陪伴状态下，最多给极轻的环境反馈，且**必须是"越来越安静"**（光渐柔、精灵渐睡、环境音渐弱）。设计目标是**让屏幕变得越来越无聊**，无聊到他自然想熄屏。任何"叮！陪伴 5 分钟 +3 积分"都是灾难——那是在用刺激留住一个本该睡觉的人。

### 三种奖励载体（大头都在第二天早上兑现）

1. **精灵的话（每天都给，最便宜，情感分量最重）**。开门第一句就带着昨晚的记忆——熄屏早睡："昨晚你早早熄了灯，今天气色真好"；亮屏陪到打烊："昨晚你陪我待到铺子睡着，谢谢你"；熬夜了也不指责："今天铺子有点困，咱们慢慢来"。这是产品温度的主力。
2. **铺子今天的状态（中频，走世界观逻辑，不走赤裸数值）**。因果必须顺：不是"陪伴 +10 换 1 客人"，而是"你昨晚好好打烊了 → 铺子休息好了 → 今天状态好 → 客人愿意上门"。让奖励藏在故事里。详见第八节"铺子状态的度"。
3. **面点精灵新皮肤（低频，长期里程碑，最珍贵）**。三条铁律：① **只靠累计、不靠连续**（断了不清零）；② **只有熄屏的夜晚才计入进度**（把最珍贵的奖励对齐最难的行为）；③ 解锁条件要**长**（隔很久得一款），它才稀有。

### 反向铁律：不惩罚

激励表里"惩罚"那一栏**永远是空的**。熬夜的唯一后果是"铺子今天安静些、客人少些、精灵打个哈欠"——这是"少得到一点热闹"，是**自然结果，不是惩罚**。用户永远不该因为打开 App 而感到愧疚。这是产品能否成立的底线。

> 防刷设计：陪伴时长**不做线性累加**（否则用户会亮屏躺床上耗时间，比刷手机还伤），做成一个**二元小成就**——"昨晚你安静地陪铺子打烊了"，达成即可。真正给厚奖励的是熄屏。

## 八、核心循环：铺子的一天

### 清晨：开门（这一格有双重任务）

用户早上打开 App = 铺子开门。这一格要同时干两件事，**编排节奏的关键是"先迎接、再结算昨天、再开启今天"，绝不一股脑砸信息**：

- **先迎接**：精灵用一句温柔的、带着昨晚记忆的话把人接住（不让他一睁眼就"干活"）。
- **结算昨天（轻）**：兑现昨晚的反馈——精灵记得你昨晚打烊/熄屏了没，铺子状态体现昨晚好坏，该解锁的皮肤进度在此推进。"开门时刻"同时是天然的"我醒了"信号（见第十节）。
- **开启今天**：记录今早的早餐（铺子菜单新增一道菜）；看今天来了哪些客人；感受今天铺子的样子。没有自动数据的话，小黑板温柔补问"昨晚大概几点放下手机的呀？"

### 白天：逛铺子

随时可打开闲逛：翻客人图鉴、翻早餐图鉴/菜单看收集进度、看营业日志（睡眠数据回顾）、跟精灵随便聊两句、（可选）装修铺子。**精灵全天候可聊，但永远是"你想聊才聊"，无最短时长、无任务感。**

### 傍晚：准备打烊（约 10 点，AI 的核心窗口之一）

此刻用户还理智，AI 接得住，所以这是傍晚最有价值的一下：

1. **预承诺 + 卸下心事**。精灵问"今晚打算几点关门？"，可展开成一小段对话："今晚有什么放不下的事吗？"——若用户说"还有个 PPT 没弄完"，它趁清醒帮你拆："非今晚不可吗，还是明早头脑清楚了半小时能搞定？" 这是 CBT-I"睡前清空大脑待办"的标准做法，用搭档聊天的方式做，不像填表。**预承诺与卸心事一次完成。**
2. **明天预告**。设完时间，给一眼明早预告："明天阿橘说好要来吃油条——你早点开门它就能吃上。" 把"早睡"翻译成"我答应了客人"，顺便复习"我是老板、客人依赖我"的因果链。
3. **清柜台小仪式（可选）**。老板打烊都要收摊：今天来了哪些客人、记了什么早餐、铺子今天的样子——给一天画句号。可省。

### 夜晚：打烊（解开 v1 的死结）

到了用户设的关门时间：

1. 精灵先给一个**通知**：要打烊了。
2. App 出现**打烊界面**——注意主语：出现的是"**铺子要打烊了**"，不是"你该睡了"。因为你是老板、因为有"只做早点不做宵夜"的店规，同样一个动作就从"被管"变成了"我作为老板该收摊了"。这正是"用户当老板"埋下的扣子在此解开 v1 的死结。
3. 用户操作**仪式感界面**：关灯 / 拉卷帘 + 几次呼吸（原"呼吸引导"在此归位为打烊仪式）。
4. 仪式最后一屏**不是"晚安"，而是"铺子睡了，把手机也放下吧，扣过来放远一点"**——一个增加"再次拿起成本"的物理动作，比任何话术都管用。
5. 完成 = 记录"今晚关门时间"（也即睡眠开始时间，见第十节）。
6. 之后进入**熄灯陪伴状态**：铺子安静、精灵打哈欠、轻微环境光。可引导"你也可以把屏幕关掉，铺子会自己守着夜，明早见"——熄屏是最好的结局。

> 若用户没在设定时间打烊，也不催、不提醒、不惩罚——第二天铺子安静一些而已。

## 九、检测机制：从"监控"到"在场证明"（v4 拍板）

### 能做到什么（能力边界）

不去窥探用户切到了哪个 App（隐私雷区，也拿不到），只用系统白送的"**我的 App 还在不在前台**"信号：

- **网页 / 原型阶段**：`visibilitychange` 事件——用户切走或熄屏立刻收到通知，切回也立刻知道。hackathon 用它就够。
- **iOS**：系统的"进入后台 / 回到前台"回调，同样只知道"我不在前台了"，不知道他去了哪（苹果锁得很死）。
- **安卓**：理论上有 `UsageStatsManager` 能看设备整体使用，但要用户授一个吓人的权限，hackathon 阶段不碰。

**结论**：可靠地知道"他离开了 App / 熄屏了"，不知道他去了哪。

### 怎么用：奖励在场，而非抓逃跑

同一个信号，用法决定生死。**绝不**做成"你敢切走我就记你一笔"的监工（会被卸载、也防不住、还制造愧疚，违背产品灵魂）。正确用法是反过来：

- App 还在前台亮着 = 他没去刷别的 = 这段"留在铺子里"的时间是今晚的成果（但只做二元小成就，不刷时长）。
- 中途切走 = 铺子不指责、不弹窗，只安静地暗下去；切回来精灵还在，"哎你回来啦"。
- 熄屏 = 最好的结局，铺子自己守夜，重奖留给它。

**测同一件事，一个让人想卸载（监控），一个让人想留下（陪伴）。**

## 十、睡眠数据采集（v4 重构：从独立方案到核心循环的副产品）

### 核心转变

v3 把睡眠检测当成一套独立的、需要用户额外配合的功能（自报 / 手环 / Tappigraphy 三层）。v4 发现：**核心循环的动作本身就把数据测了。**

- **睡眠开始时间** = 打烊 / 熄屏时刻。打烊仪式本质上就是用户主动报告"我现在要放下手机了"；熄屏被 `visibilitychange` 测到。比偷偷做 Tappigraphy 更好——主动、有仪式感、无隐私窥探。
- **醒来时间** = 早上开门、打开 App 的时刻（天然的"我醒了"信号）。
- **打烊 + 开门首尾夹出一段睡眠窗口**——你为了世界观本来就要做的两个动作，顺带产出了数据。

### 三层方案重新归位

| 来源 | v4 中的角色 |
|------|------------|
| 打烊 + 开门（核心循环白送） | **主力数据源**，取代了原本要单独做的 Tappigraphy |
| 用户自报（原第一层） | **兜底**，窄化为"没好好打烊 / 切走熬夜了的夜晚"补问 |
| HealthKit / 手环（原第二层） | **精度增强**，给有设备的用户校准"打烊到真正睡着"的差，锦上添花 |

### 连带的优雅效果

睡眠数据从"一个需要用户配合的额外动作"变成"玩这个世界自然产出的副产品"。用户不觉得自己在记录睡眠，他只是在打烊、在开门——动机内置在世界里了。

### 不防作弊的设计哲学（保留）

用户可以每天报告自己 10 点就睡了，不验证、不质疑。理由：铺子从不惩罚晚睡，用户没有作弊动机；骗一个不评判你的 App 没有好处——你骗的是自己的日记。

## 十一、铺子状态的"度"（v4 新增）

### 原则：状态跟"近期趋势"挂钩，不跟"昨晚单点"挂钩

只看昨晚 → 一晚好坏让铺子天翻地覆，用户被单次表现绑架。看近期整体 → **偶尔熬一次几乎不影响铺子**，这正是"不惩罚、断签不清零"灵魂在视觉上的体现。

### 三档 + 底部保护

不做连续无级变化（用户会盯细微差别患得患失），做 3 档：

- **热闹**：近期作息整体不错。铺子明亮、客人多、有概率出稀有客人。
- **平常**：默认态，绝大多数时候看到的样子，基准线。
- **安静**：近期普遍熬得晚。铺子光柔、客人少、精灵打哈欠。

两条关键的度：

1. **最差也就"安静"，永远不会"关门 / 没人 / 凄凉"**。安静 ≠ 荒废。哪怕连熬一周，铺子也只是暖光里静悄悄，门还开着、精灵还在。这道底部保护线是"铺子明天还在"的视觉承诺，绝不能击穿。
2. **向上慢、向下更慢**。变好要几天好趋势累积（让"热闹"值得追求）；变差更迟钝（偶尔一两晚几乎不下掉）。这个不对称是故意的——**让好行为被看见，让偶尔的失手被原谅。**

稀有客人 / 特殊事件作为"热闹"档之上的随机惊喜（可变奖励），不是每次热闹都触发，偶尔撞见才有期待感。

> 一句话：铺子状态是你近期作息的一面**慢镜子**——好起来要努力几天，坏下去要连续辜负很久，且永远不会真的冷场。

## 十二、客人系统（小动物）

### 本质

客人不是"早睡的奖励物品"，是铺子里有名字、有性格、有固定口味的角色。独立于面点精灵（精灵是伙伴，不进客人池）。

### 怎么来

铺子状态决定今天来多少、来哪些：关门越早今天客人越多；连续多天早关门 → 稀有客人出现；特殊条件（连续早睡到某程度、节日、特定时段）→ 隐藏客人。

### 客人图鉴

每个客人一页档案：头像、名字、性格签名、最爱的早餐、来店次数、第一次来的日期。未解锁显示模糊剪影 + 解锁提示。

### 行为（demo 先简单版）

demo 阶段：客人静态出现，不同时段显示不同状态即可（早上吃早餐、下午闲坐、晚上离开）。复杂动态行为留给后续版本。

## 十三、早餐系统

### 早餐记录

每天早上记录今天吃了什么 → 铺子菜单新增一道菜。不评判、不打分、不分析营养。"不论今早吃的是什么，都值得被记一笔。"

### 早餐图鉴（菜单墙）

展示所有已解锁 / 未解锁菜品。每道菜有名字、插画、哪些客人喜欢、做过多少次。

### 限定菜品（商业模式入口）

节日限定（中秋月饼、冬至汤圆）、品牌联名（连锁早餐 / 咖啡品牌）。

### 早餐墙（可翻转日历，来自灵感对话）

按日历一天一格，每张卡片可翻转：正面是真实早餐记录，背面是铺子回赠的"数字早点"。没记录的那天是空格，点了会提示"补不回来的——那个早晨没被记下"。（与早餐图鉴是否合并，待定。）

## 十四、产品灵魂（不变）

从 v1 到 v4，形态变了很多，以下原则从未改变，且 v4 把它们从"话术"落成了"机制"：

1. **永远站在用户这边，失败时尤其如此。** 铺子安静一天不是惩罚，是"没关系，明天见"。
2. **不替用户做决定。** 几点关门你说了算。
3. **不评判。** 早餐不分健康不健康，熬夜不分好坏，铺子只记录。
4. **不假装能解决根本问题。** 不承诺让你早睡，承诺的是：无论你今晚怎样，明天它都在，而且温柔。
5. **（v4 强化）不让用户因打开 App 而愧疚。** 检测用于奖励在场，不用于抓逃跑；激励表里没有"惩罚"那一栏。

## 十五、技术架构（v4 更新）

### 前端
- React 网页端原型（hackathon 阶段）；正式版可 React Native / Flutter。

### 在场检测 / 放下手机判定
- `visibilitychange`（前后台 + 熄屏信号）。这是 v4 检测机制的技术落点，原型用它即可跑通。

### 睡眠数据
- 主力：打烊（关门时间）+ 开门（醒来时间）由核心循环产出。
- 兜底：用户自报（前端表单，仅用于没好好打烊的夜晚）。
- 增强：HealthKit / Health Connect（有设备用户）。

### AI 对话
- Claude API。**六套人格 system prompt 保留并启用**——它们决定面点精灵的灵魂内核。
- AI 重心在早晨（开门回应、记得昨晚）与傍晚（预承诺、卸心事），外加营业日志的"店长解读"。凌晨绝不主动出现。
- 对话内核随营业日志的作息变化做话题自适应。

### 数据存储
- 本地为主（睡眠记录、客人图鉴、早餐图鉴、精灵皮肤进度）；云端可选（跨设备同步、社交）。

## 十六、赛道契合与评审对齐（路演用）

**赛道：AI + 健康生活。** v4 的设计对齐如下：

- **健康场景命中**：直接落在赛道明示的"健康习惯养成、身心情绪调节、精细化健康提醒"上。
- **AI 看得见**：用户真的在跟面点精灵对话，AI 由六套人格 prompt 驱动、记得你、每天不同——这是 AI 赛道想要的"亲眼看见在和聪明 AI 互动"的瞬间，不是藏在幕后的装饰。
- **AI 不在凌晨干预**：重心在早晚两个用户接得住的窗口，正面回应了"凌晨没有自控力"这条自家洞察。
- **健康产出看得见**：营业日志 + 精灵的"店长解读"，把作息改善具象化，堵住"你到底帮用户健康了没"的质疑。
- **低技术成本、强落地性**：检测靠系统白送的 `visibilitychange`，数据靠核心循环副产品，符合 Vibe Coding 低门槛理念。

**路演叙事**："我们最初做了一个 AI 对话助眠 App。但我们自己问：凌晨 1 点刷手机的人会打开它吗？答案是不会。于是我们重新思考——从'帮你入睡'变成'一家你自己经营的温柔早点铺'。所有旧功能没被扔掉，而是在新框架里找到了更好的位置。" 这个"做了 → 质疑 → 进化"的叙事本身就是最有力的展示。

## 十七、待解决的问题（v4 更新）

v3 中已解决并从此列移除的：角色定位（用户当老板）、AI 定位（面点精灵）、AI 在世界观里的位置、目标边界（放下手机）、检测机制、激励梯度、铺子状态的度、睡眠数据采集方案、伙伴系统全部设定。

仍待敲定：

1. 铺子的美术风格（手绘暖调 vs 像素复古 vs 其他）——现在可以推进了。
2. 面点精灵各点心形态的具体设计（demo 先做 2–3 款）。
3. 打烊仪式的具体交互形式（关灯 / 拉卷帘 / 吹蜡烛，选哪个）。
4. 铺子的时间是否跟现实同步（影响客人在不同时段的状态）。
5. 早餐墙（可翻转日历）与早餐图鉴是否合并。
6. 铺子状态三档的具体触发阈值（"近期"是几天的窗口、各档的数值边界）。
7. 皮肤解锁的具体里程碑设计（累计多少个熄屏夜晚解锁一款）。
8. 铺子装修 / 个性化系统的深度。
9. 社交功能（看朋友的铺子？）——优先级低。
10. 商业模式的具体落地路径（限定 / 联名早餐、装饰性皮肤内购，绝不卖"补回断签"）。
